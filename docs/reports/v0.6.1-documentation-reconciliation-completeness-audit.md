## 16. Accepted verification deviation A: disposable second install

- Reason: the installed CLI only accepts case targets inside its own package root (`Resolved path escapes target root`), so a temporary copied target outside the package cannot be used, and relaxing containment would be product work.
- Code evidence: the sandbox is a second `npm install` of the same `tarballPath`; the primary install and the canonical and installed benchmarks are snapshotted and must not change; the sandbox diff must be exactly one file, `benchmarks/projects/task-workflow-medium-ts/src/store/taskStore.ts`; all output is written under the verifier workspace.
- Verdict: **ACCEPTED.** It is verifier-owned temporary state, not a product limitation or new product functionality.

## 17. Accepted verification deviation B: mutation after the first delegated search

- Reason: Lab captures `IndexSnapshotV1` immediately after the index build, so a mutation at index return would already be inside the baseline hash and produce fresh evidence.
- Code evidence: the wrapper delegates every command to the real upstream CLI and mutates only after a delegated `search` that follows a successful `index`, exactly once. The verifier requires one successful index, identical file SHA-256 before the index, after the index, and before the mutation, a different SHA afterwards, and the index log line before any `search`. It requires Lab's snapshot hash to equal the pre-mutation SHA, task 1 `fresh`, task 2 `stale` with `changedFileCount` 1 and a change record whose baseline and current hashes match the wrapper state, and then `related` and `recommended`.
- Verdict: **ACCEPTED.** Product runtime was not altered.
