## 27. v0.4.9 specific readiness review

**A. Action vocabulary** — `TUTORIAL_ACTION_TYPES` is exactly `goto, click, fill, press, hover, drag, select-option, wait-for, pointer-click, pointer-drag`.

**B. `select-option` semantics** — value-only; native `<select>`; required non-empty trimmed value; passes only when exactly one returned value equals the requested value; no label, no index, no multi-select, no keyboard fallback.

**C. Existing interaction behavior** — `press` still calls `locator.press(action.key, …)` (real keyboard input); `drag` still calls `source.dragTo(target)`; `pointer-click` and `pointer-drag` still resolve locator-relative fraction coordinates through `resolveTutorialFractionPoint`.

**D. Schemas** — `TutorialScenarioV1`, `TutorialTargetContractV1`, `TutorialRunResultV1`, `TutorialManifestV1` all `1.0.0`.

**E. Package version** — `0.4.8`.

**F. Generic fixture** — 10 steps, `select-operation` at step 9, `wait-banner` at step 10.

**G. Installed-package proof** — `TUTORIAL_SELECT_OPTION` exists and passes.

**H. Security** — no scenario-controlled JavaScript, `page.evaluate`, `dispatchEvent`, DOM property mutation, shell command, arbitrary browser method, or arbitrary event payload. Within `src/`, `page.evaluate` appears only in `tutorialCursor.ts` and `tutorialOverlay.ts`, which install the tutorial's own fixed presentation DOM and accept no scenario input; no action, assertion, or locator kind carries script text. The only `.exec(` in `scenarioValidation.ts` is a regular-expression `exec` used for JSON Pointer escape validation, not process execution. The `page.evaluate` in `tests/integration/tutorialRealBrowser.spec.ts` is test-owned instrumentation that wraps the page object and is unreachable from any scenario.

## 31. Known risks and accepted limitations

- `select-option` is value-only: no label, index, multi-select, or automatic selector fallback, and no keyboard fallback.
- Native popup/menu traversal is not modeled; hidden-select behavior has no dedicated fixture case.
- The action relies on Playwright's `selectOption` actionability behavior, and the strict single-returned-value check intentionally enforces the single-select contract.
- CodeQL and OSV-Scanner did not run locally; both are optional and covered by repository policy, with CodeQL analysis running through GitHub code scanning.
- Five informational outdated-dependency notices exist (`@types/node`, `playwright`, `tsx`, `typescript`, `vitest`). None is a vulnerability — both `npm audit` runs report zero. `playwright` is deliberately pinned at `1.60.0` and asserted by `tests/scripts/packageScriptContract.spec.ts`; upgrading it during readiness would break that pinned contract and invalidate the validated candidate.
- Chromium remains a separately installed local runtime prerequisite; neither installation nor tutorial execution downloads it.
