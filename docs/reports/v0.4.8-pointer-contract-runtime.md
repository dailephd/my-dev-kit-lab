## 6. Consumer blocker

The released v0.4.7 tutorial action vocabulary cannot express two distinct positions inside one SVG/canvas-style interaction surface.

## 7. Root cause

The existing `drag` action deliberately models element-to-element drag-and-drop through `sourceLocator.dragTo(targetLocator)` and has no bounded locator-relative position contract.

## 8. Existing drag contract preserved

`drag` remains `{ type, source, target, timeoutMs? }` and still executes exactly one locator `dragTo()` operation.

## 9. pointer-click serialized contract

```ts
{
  type: "pointer-click";
  locator: TutorialLocatorV1;
  position: { x: number; y: number };
  coordinateSpace: "fraction";
  timeoutMs?: number;
}
```

## 10. pointer-drag serialized contract

```ts
{
  type: "pointer-drag";
  locator: TutorialLocatorV1;
  from: { x: number; y: number };
  to: { x: number; y: number };
  coordinateSpace: "fraction";
  timeoutMs?: number;
}
```

## 11. Fraction coordinate contract

Both axes require finite numbers within inclusive `[0, 1]`. Objects are closed to exactly `x` and `y`; values are not clamped, rounded, or coerced. `pointer-drag` rejects identical endpoints.

## 12. Schema-version decision

`TutorialScenarioV1`, `TutorialTargetContractV1`, `TutorialRunResultV1`, and `TutorialManifestV1` remain schema version `1.0.0`. The additive action discriminants do not invalidate existing scenarios; the future package version is the capability boundary.

## 13. Geometry owner

`src/tutorial/tutorialPointerGeometry.ts` owns pure locator-box plus fraction conversion and finite positive-box validation. It does not resolve locators or execute mouse input.

## 14. Structural Playwright mouse additions

`PlaywrightLikeTutorialPage` now requires a narrow `mouse` surface with `move(x, y, options?: { steps?: number })`, `down()`, and `up()`. `PlaywrightLikePage` is unchanged.

## 15. pointer-click runtime

Resolve canonical locator; wait for visible; read bounding box; resolve the fraction; call `mouse.move`; call `mouse.down`; call `mouse.up`; return the unchanged action-result shape.

## 16. pointer-drag runtime

Resolve canonical locator; wait for visible; read one bounding box; resolve both endpoints from that box; call `mouse.move(start)`; call `mouse.down`; call `mouse.move(end, { steps: 8 })`; call `mouse.up`; return the unchanged action-result shape.

## 17. mouse-up cleanup behavior

No cleanup is attempted when `down()` fails. After a successful `down()`, `up()` is attempted exactly once. A primary movement error remains primary; an additional cleanup failure is appended as bounded context. An `up()`-only failure fails the action. Gestures are never retried.

## 18. Synthetic cursor behavior

`pointer-click` plans the declared fraction before real input. `pointer-drag` plans the declared start before real input and moves to the planned end only after success. Existing center-based click/fill/press/hover and source-center/target-center drag behavior remains intact. Presentation failures remain warnings.

## 19. Click-feedback behavior

Successful `pointer-click` reuses `showTutorialClickFeedback()` and `CLICK_FEEDBACK_DURATION_MS` at the exact planned fraction point.

## 20. Security boundary

Closed validation rejects page/screen coordinates, element-pixel mode, arbitrary JavaScript, scripts, events, event types, mouse-button configuration, pointer types, and configurable steps. No dispatch-event, shell, touch, or pen action was added.

## 21. Validation tests

## 22. Action execution tests

## 23. Visual/session tests
