## 15. Materialization/manifest audit

`materializeSyntheticRepository` verifies the plan, renders, builds the manifest, resolves paths with the shared path-safety primitive, stages in a temporary child of the output root, verifies the staged tree against the manifest, then renames atomically; an existing identical materialization is reused without rewriting and any foreign, drifted, or incomplete child is a collision. Staging is removed only on failure of its own write. UTF-8/LF/no-BOM, exact dimensions, manifest schema `1.0.0`, no host/time/PID/cwd/staging identity, and a read-only verifier are covered by `render` and `materialize` specs.
