## 3. Consumer blocker

The released tutorial vocabulary could drag one element to another but could not express two positions inside one SVG or canvas-like pointer surface. That blocked downstream annotation gestures even though raw Playwright mouse input worked.

## 4. Root cause

The v0.4.7 `drag` action intentionally delegates to `sourceLocator.dragTo(targetLocator)`. It had no locator-anchored fractional start and end points. Prompt 1 added the bounded pointer actions; this prompt supplies end-to-end browser and package evidence.

## 5. Existing drag semantics

The canonical `drag-card` step remains unchanged and passes using the element-to-element `drag` action. It coexists with the new single-locator `pointer-drag` action.

## 6. New pointer action contract

`pointer-click` uses one `TutorialLocatorV1`, a required `{ x, y }` position, required `coordinateSpace: "fraction"`, and optional timeout. `pointer-drag` uses one locator, required `{ x, y }` `from` and `to` points, the same required coordinate space, and optional timeout. No public contract changed in Prompt 2.

## 7. Coordinate model

Coordinates are fractions within the resolved locator bounding box, inclusive from 0 through 1. The canonical click is `(0.25, 0.25)` and the canonical drag is `(0.20, 0.25)` to `(0.80, 0.75)`. The fixture asserts categorical zones instead of exact browser coordinates.
